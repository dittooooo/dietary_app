你現在要協助我整理「慢性疾病飲食規則資料」，目標是產出可直接用於 Knowledge Graph 與 Recommendation System 的 JSON 檔案。

請你依照 workspace/src/chronic_disease_rules 資料夾中現有的程式碼、資料格式與附檔內容進行修改與產出，不要重新設計完全不同的架構，請盡量沿用現有欄位命名、資料結構與處理流程。

一、任務目標

我要建立一份慢性疾病飲食規則 JSON。

這份資料未來會用在知識圖譜中，主要處理「疾病節點」與「營養成分節點」之間的關係。

知識圖譜的核心不是：

Disease → Food

而是：

Disease → Nutrient

食物只能作為 example_foods 或輔助說明，不應該成為疾病直接連結的主要對象。

也就是說，原始參考資料可能會寫：

高血壓應少吃鹹食、泡麵、醃漬品

但你要整理成：

高血壓 limit 鈉 Sodium

而不是：

高血壓 limit 泡麵

原因是泡麵被限制，是因為它通常含有高鈉。

三、核心知識圖譜規則

每一種疾病都要整理成 disease node 與 nutrient node 的關係。

疾病與營養成分之間只允許以下三種 relation：

1. recommend
代表此疾病建議增加、優先選擇、適量攝取的營養成分。

例如：
高血脂 recommend 可溶性膳食纖維
高血脂 recommend 不飽和脂肪
糖尿病 recommend 膳食纖維

2. limit
代表此疾病需要限制、減少、控制攝取量的營養成分。

例如：
高血壓 limit 鈉
高血脂 limit 飽和脂肪
糖尿病 limit 添加糖
慢性腎臟病 limit 鈉、磷、鉀、蛋白質

3. prohibit
代表此疾病應避免或盡量不要攝取的營養成分。

注意：
prohibit 不代表醫學上絕對禁止，而是對推薦系統而言屬於高風險、應強烈避免的項目。

例如：
高血脂 prohibit 反式脂肪
痛風 prohibit 酒精
胃食道逆流 prohibit 酒精、咖啡因或刺激性成分，可依參考資料判斷

四、資料整理原則

請將原始參考資料中的「推薦食物」、「限制食物」、「禁止食物」轉換成背後對應的營養成分原因。

轉換範例：

1. 若參考資料說「高血壓少吃泡麵、醃漬品、加工食品」
應轉換成：
疾病：Hypertension
relation：limit
nutrient：Sodium
reason：高鈉攝取會提高血壓並增加心血管風險
example_foods：泡麵、醃漬品、加工食品

2. 若參考資料說「高血脂少吃肥肉、奶油、香腸」
應轉換成：
疾病：Hyperlipidemia
relation：limit
nutrient：Saturated Fat
reason：飽和脂肪會提高 LDL-C
example_foods：肥肉、奶油、香腸

3. 若參考資料說「糖尿病避免含糖飲料、甜點」
應轉換成：
疾病：Diabetes Mellitus
relation：limit 或 prohibit
nutrient：Added Sugar
reason：添加糖會使血糖快速上升，增加血糖控制困難
example_foods：含糖飲料、甜點

4. 若參考資料說「痛風避免內臟、海鮮、啤酒」
應轉換成：
疾病：Gout
relation：limit 或 prohibit
nutrient：Purine 或 Alcohol
reason：高普林食物與酒精會提高尿酸生成或影響尿酸代謝
example_foods：內臟、部分海鮮、啤酒

五、每個疾病 JSON 格式

每一個疾病都應整理成以下格式。

請注意：
1. disease_name_zh 使用繁體中文
2. disease_name_en 使用英文正式名稱
3. disease_nutrient_relations 是主要資料
4. example_foods 只是輔助，不是主要關係
5. 所有 target_rule 與 food_level_rule 都要盡量保留可被系統判斷的欄位
6. 無法確定精準數值時，可以標記為 null 或寫明「需依資料庫校正」，但不要亂編過度精確的數字

資料格式如下：

{
  "disease_id": "hyperlipidemia",
  "disease_name_zh": "高血脂",
  "disease_name_en": "Hyperlipidemia",
  "disease_nutrient_relations": [
    {
      "relation": "recommend",
      "nutrient_name_zh": "可溶性膳食纖維",
      "nutrient_name_en": "Soluble Fiber",
      "target_rule": {
        "daily_target": "5–10 g/day",
        "unit": "g/day",
        "direction": "increase",
        "note": "有助降低 LDL-C"
      },
      "food_level_rule": {

        "basis": "per_100g",
        "level": "rich",
        "operator": ">=",
        "amount": 3,
        "unit": "g",
        "note": "此為系統判斷門檻，可依台灣營養宣稱標準或資料庫分布再校正"
      },
      "example_foods": ["燕麥", "大麥", "豆類", "蘋果", "梨子", "秋葵", "茄子"],
      "reason": "可溶性纖維可降低膽固醇吸收，幫助改善 LDL-C"
    }
  ],
  "diet_pattern": {
    "recommended_patterns": ["地中海飲食", "DASH"],
    "core_principle": "提高纖維與不飽和脂肪，限制飽和脂肪、反式脂肪、膽固醇、添加糖與高鈉"
  },
  "risk_notes": [
    "此資料用於飲食建議與知識圖譜推論，不可取代醫師診斷或藥物治療",
    "若使用者同時有其他慢性疾病，應合併其他疾病規則重新加權"
  ]
}

六、每個 disease_nutrient_relation 的欄位要求

每一筆 disease_nutrient_relation 至少包含：

1. relation
只能是 recommend、limit、prohibit 三者之一。

2. nutrient_name_zh
繁體中文營養成分名稱。

3. nutrient_name_en
英文營養成分名稱。

4. target_rule
描述每日目標、限制、方向、單位、注意事項。
常見欄位可以包含：
daily_target
daily_limit
weekly_target
max
optimal
unit
direction
note

direction 只能使用以下語意：
increase：建議增加
decrease：建議減少
avoid：建議避免
replace：建議取代
maintain：建議維持
adjust_by_stage：依疾病階段調整

5. food_level_rule
用於推薦系統判斷某個食物或料理是否符合高風險或推薦條件。
常見欄位可以包含：
basis
level
operator
amount
unit
condition
note

basis 只能使用：
per_100g


6. example_foods
保留原始參考文件中提到的代表性食物。
注意：這只是輔助說明，不是知識圖譜主要關係。

7. reason
用一句話說明此疾病為什麼和這個營養成分有關。

七、疾病整理方向

請依照以下疾病特性整理，但仍需根據參考文件內容修正。

1. Hypertension 高血壓
常見營養關係：
limit sodium
recommend potassium
recommend dietary_fiber
limit saturated_fat
limit alcohol
diet_pattern 可包含 DASH

2. Hyperlipidemia 高血脂
常見營養關係：
recommend soluble_fiber
recommend omega_3_fatty_acids
recommend unsaturated_fat
limit saturated_fat
prohibit trans_fat
limit cholesterol
limit added_sugar
limit sodium

3. Diabetes Mellitus 糖尿病
常見營養關係：
limit added_sugar
limit refined_carbohydrate
recommend dietary_fiber
limit sodium
limit saturated_fat
recommend low_glycemic_index_carbohydrate
需注意碳水化合物總量與血糖影響

4. Cardiovascular Disease 心血管疾病
常見營養關係：
limit sodium
limit saturated_fat
prohibit trans_fat
limit cholesterol
recommend dietary_fiber
recommend unsaturated_fat
recommend omega_3_fatty_acids
limit added_sugar

5. Chronic Kidney Disease 慢性腎臟病
常見營養關係：
limit sodium
limit protein 或 adjust_by_stage protein
limit potassium
limit phosphorus
limit fluid 視情況
需特別標記：慢性腎臟病飲食限制會依疾病分期、是否洗腎而不同，不可用單一規則套用所有人

6. Stroke 腦中風
常見營養關係：
limit sodium
limit saturated_fat
prohibit trans_fat
recommend dietary_fiber
recommend potassium
recommend unsaturated_fat
limit added_sugar
主要目標是控制血壓、血脂、血糖與心血管風險

7. Metabolic Syndrome 代謝症候群
常見營養關係：
limit added_sugar
limit refined_carbohydrate
limit saturated_fat
prohibit trans_fat
recommend dietary_fiber
recommend unsaturated_fat
limit sodium
與腹部肥胖、血壓、血糖、三酸甘油脂、HDL 有關

8. Gout 痛風
常見營養關係：
limit purine
prohibit alcohol 或 limit alcohol
limit fructose
recommend water
limit organ_meat
注意：若系統只連營養成分，內臟、海鮮等應放在 example_foods，主要 nutrient 應是 purine

9. Hyperuricemia 高尿酸血症
常見營養關係：
limit purine
limit alcohol
limit fructose
recommend water
與痛風類似，但可比痛風稍微偏向預防與控制尿酸

10. Gastroesophageal Reflux Disease 胃食道逆流
常見營養關係：
limit fat
limit caffeine
limit alcohol
limit spicy_compounds
limit acidic_food_components
limit carbonated_drinks
注意：此疾病常與症狀觸發食物有關，因此 food_level_rule 可使用 symptom_trigger
