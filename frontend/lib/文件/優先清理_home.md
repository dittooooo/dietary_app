## 1. `home_view.dart` 集中太多互不相同的功能

- **檔案與行號**：`views/home/home_view.dart:23-2781`
- **原始碼片段**：同一個 `_HomeViewState` 同時處理語音辨識、聊天快取、飲食紀錄摘要、體態同步、導航、對話草稿、動畫與多個 UI Painter／Widget。
- **原因**：檔案接近 2,800 行，任何 API、狀態或 UI 修改都可能影響其他功能；也讓 loading、mounted 與錯誤狀態難以完整測試。
- **優先度**：優先度中
- **難易度**：難易度困難
- **目前證據**：方法範圍從語音與快取一路延伸至 `_showMealRecordDraftDialog()` 和檔案尾端的多個 UI 類別；這是目前檔案結構可直接確認的問題。
- **驗證方式**：先按功能畫出資料流，再依序驗證語音、聊天、昨日摘要、體態同步、飲食草稿與頁籤返回。
- **完成條件**：首頁 State 只保留頁面狀態與流程編排；聊天、摘要、體態與草稿儲存有清楚邊界，既有畫面行為不變。

## 2. 首頁仍有未使用方法與重複寵物／餵食導航

- **檔案與行號**：`views/home/home_view.dart:796`、`1074-1100`、`1188-1219`、`1569-1574`、`1767-1848`
- **原始碼片段**：`_triggerYesterdaySummary()` 有 `ignore: unused_element`；`_buildSummaryRow`、`_buildNutrientItem`、`_getPetIcon`、`_getPetImagePath`、`_buildLegendDot` 目前只有定義或沒有有效呼叫；兩處都建立 `ElfFeedingPage`。
- **原因**：保留未使用流程會讓維護者誤以為它是正式入口；兩處餵食導航若參數或儲存契約不同，會造成相同操作結果不一致。`_getPetColor` 目前仍有有效使用，不應誤刪。
- **優先度**：優先度中
- **難易度**：難易度簡單
- **目前證據**：全專案搜尋確認 `_triggerYesterdaySummary` 等方法的呼叫情況；`ElfFeedingPage` 在首頁有兩個有效建立處。
- **驗證方式**：逐一搜尋呼叫端，確認未使用方法不是動態反射或測試入口；測試兩個餵食入口的日期、餐點、動畫與返回流程。
- **完成條件**：刪除確認無入口的死碼；餵食導航集中為單一契約；寵物顯示名稱不再由首頁硬編碼決定。

## 3. `home_page.dart` 的角色檢查與頁籤配置重複

- **檔案與行號**：`views/home/home_page.dart:46-236`
- **原始碼片段**：`_applyUserConfig()` 與 `_applyAdminConfig()` 目前建立相同的四個頁面，只有管理員多一個強制補資料 Dialog。
- **原因**：角色判斷、頁籤配置與強制補資料流程混在一起；未來新增或刪除頁籤時容易只改其中一邊。
- **優先度**：優先度中
- **難易度**：難易度中
- **目前證據**：兩個配置方法的 `_pages` 內容目前相同；這不是把管理員功能誤判成無用，而是重複配置風險。
- **驗證方式**：測試一般帳號、管理員帳號、角色載入失敗與角色切換後的四個頁籤及強制 Dialog。
- **完成條件**：共用頁籤配置只保留一份；管理員額外行為以獨立條件處理。
