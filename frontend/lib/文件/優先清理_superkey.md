## 1. 餐廳與菜單管理方法是安全拔除候選

- **檔案與行號**：`services/admin_service.dart:154-203`。
- **原始碼片段**：`listRestaurants()`、`createRestaurant()`、`updateRestaurant()`、`deleteRestaurant()`、`listMenuItems()`、`createMenuItem()`、`updateMenuItem()`、`deleteMenuItem()`。
- **原因**：目前這些方法回傳空清單、`false` 或「已從前端移除」訊息，沒有實際管理頁面呼叫它們；保留會讓人誤以為餐廳／菜單後台仍可用。
- **優先度**：優先度中
- **難易度**：難易度簡單
- **目前證據**：全 `frontend` 靜態搜尋未找到上述方法的外部呼叫；只有方法定義本身存在。這是可安全拔除的候選，不代表可跳過最後一次路由／deep link／測試入口確認。
- **驗證方式**：搜尋 Navigator、路由表、deep link、測試工具與文件入口；確認後台 UI 沒有隱藏入口。
- **完成條件**：確認無入口後移除這些 stub 與不再需要的 import／註解；完成管理員登入與個人頁 smoke test。

## 2. 後台飲食紀錄管理方法是安全拔除候選

- **檔案與行號**：`services/admin_service.dart:204-289`。
- **原始碼片段**：`listDietRecords()`、`updateDietRecord()`、`deleteDietRecord()` 仍呼叫 `/admin/diet-records...`。
- **原因**：目前全專案靜態搜尋未找到後台飲食紀錄頁或這三個方法的外部呼叫，但 service 仍保留完整查詢、修改與刪除流程；它會持續增加管理 API 契約與錯誤處理維護成本。
- **優先度**：優先度中
- **難易度**：難易度中
- **目前證據**：方法定義仍存在，但 `frontend/lib` 沒有對應管理頁檔案或呼叫點；刪除前仍需確認外部路由與產品需求。
- **驗證方式**：確認沒有動態字串呼叫、管理後台外部頁面或測試工具依賴；確認一般使用者的 `DietService` 飲食紀錄流程不使用 `/admin/diet-records`。
- **完成條件**：確認無入口後移除後台飲食紀錄方法與相關 response helper；一般飲食紀錄新增、修改、刪除 smoke test 通過。

## 3. 正式使用者管理頁需維持狀態刷新與刪除契約

- **檔案與行號**：`views/superkey/admin_user_list_page.dart:35-61`、`270`、`417-463`；`services/admin_service.dart:31-151`。
- **原始碼片段**：頁面呼叫 `listUsers()`、`updateUserStatus()`、`createUser()`，並在操作後自行 `setState` 重新載入。
- **原因**：這是目前仍在使用的後台功能，不能因清理孤立頁面而一起刪除；狀態切換、建立使用者、刪除／停用行為與錯誤提示必須和 service 回傳契約一致。
- **優先度**：優先度中
- **難易度**：難易度中
- **目前證據**：`profile_page.dart` 有管理頁入口 import；`admin_user_list_page.dart` 明確呼叫 `AdminService`。
- **驗證方式**：測試搜尋、啟用／停用、建立使用者、目前管理員不可操作自己、失敗後刷新與重新進入頁面。
- **完成條件**：成功後畫面資料與後端一致；失敗時不先顯示假成功狀態；刪除／停用契約與權限規則有明確測試。

## 4. 正式問題回饋頁需維護圖片路徑與回覆流程

- **檔案與行號**：`views/superkey/admin_problem_feedback_page.dart:28-70`、`125-205`；`services/admin_service.dart:373-410`。
- **原始碼片段**：頁面載入回饋、顯示 `Image.network(...)`、開啟回覆 Dialog，再呼叫 `replyProblemFeedback()`。
- **原因**：這是目前在用的功能；圖片 URL 若未經統一解析可能在不同環境失效，回覆成功後若未刷新會顯示舊狀態或重複提交。
- **優先度**：優先度中
- **難易度**：難易度中
- **目前證據**：頁面直接呼叫 `listProblemFeedback()` 與 `replyProblemFeedback()`；不是孤立後台檔案。
- **驗證方式**：測試相對／完整圖片 URL、圖片載入失敗、空回饋、回覆成功／失敗、重複點擊與回覆後重新載入。
- **完成條件**：圖片路徑走統一 URL 規則；回覆按鈕有 loading／防重複提交；成功後清楚更新畫面，失敗不覆蓋原內容。

## 5. 後台測試工具不是餐廳／菜單／飲食紀錄管理頁

- **檔案與行號**：`views/superkey/admin_test_tools_page.dart:14-940`。
- **原始碼片段**：頁面使用 `DietService().getMyDietRecords()` 顯示測試報告與圖表，並有自己的營養圖表 Painter。
- **原因**：刪除管理餐廳、菜單、後台飲食 CRUD 時，不應誤刪目前仍可由個人頁進入的測試工具；需把「頁面用途」與「AdminService 的孤立方法」分開。
- **優先度**：優先度中
- **難易度**：難易度中
- **目前證據**：搜尋確認測試工具使用一般 `DietService`，不是 `AdminService.listDietRecords()`。
- **驗證方式**：由管理員個人頁進入測試工具，確認報告載入與返回流程；另確認拔除候選方法沒有被它呼叫。
- **完成條件**：測試工具保留且功能正常；孤立管理方法獨立清理，不影響一般飲食資料查詢。
