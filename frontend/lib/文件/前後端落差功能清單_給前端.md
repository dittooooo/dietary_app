# 前後端功能落差整理清單 (給前端)

本文件詳列了目前 **後端已實作** 完整 API 邏輯，但 **前端尚未完全對接** 或僅有初步佔位的功能清單。

## 1. 登入 (Login)
*   **現況說明**：後端已實作強大的 JWT 權限管理系統，並在資料庫中區分了 `ROLE_USER` 與 `ROLE_ADMIN`。JWT Token 中已包含身分識別資訊，且所有 `/api/admin/**` 接口皆有嚴格的權限守衛。
*   **前端需補強**：目前前端對「管理員」的身分判讀邏輯分散在各頁面（如 `ProfilePage` 的手動檢查）。應在 `AuthService` 或 `ApiClient` 中統一處理身分判別，並實作 **「權限降級處理」**，當一般使用者試圖存取管理頁面回傳 403 時，應有友善的導航攔截。

## 2. 個人首頁 (Profile)
*   **現況說明**：後端 `AdminController` 已具備完整的 **使用者管理 (User Management)** 功能，支援搜尋關鍵字、單筆查詢、新增、修改與物理刪除使用者帳號。
*   **前端需補強**：目前的「使用者管理」頁面僅具備基本列表。需補齊 **「管理員操作面板」**，實作點擊列表項後跳轉至使用者詳情頁，並能直接在 App 內執行「修改使用者權限」或「強制註銷違規帳號」的動作。

## 3. 飲食紀錄 (Dietary Records)
*   **現況說明**：後端已實作 `AdminController` 下的 `/api/admin/diet-records` 系列接口，允許管理員對 **全系統** 的飲食紀錄進行 CRUD 操作（增刪改查）。
*   **前端需補強**：前端目前「管理選單」內的「飲食紀錄管理」僅為佔位頁面。應實作 **「全系統紀錄監控台」**，讓管理員能查看所有使用者的近期進食數據，並能針對異常數據進行修正或刪除，確保系統數據的準確性。

## 4. 預設首頁 (Home)
*   **現況說明**：後端已實作 **「餐廳與菜單管理系統」** (Restaurant & MenuItem Service)，支援儲存餐廳名稱、位置資訊以及對應的餐點與熱量數據。
*   **前端需補強**：目前小精靈對話框中的「餐廳推薦」均為寫死的 Mock Data。應改為 **「動態資料串接」**：當使用者諮詢建議時，前端應向後端請求管理員已建立的「真實餐廳清單」，並動態生成餐廳卡片，而非顯示模擬的測試內容。
