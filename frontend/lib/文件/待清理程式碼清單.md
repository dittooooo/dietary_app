整理基準：2026-09-04 的目前 checkout、全專案引用搜尋，以及既有分析文件交叉比對。舊分析輸出中的路徑或行號若無法由目前原始碼重現，均標記為「需重新驗證」，不直接視為現行錯誤。

## 優先度與難易度

- `優先度最高`：編譯、執行、資料完整性或安全風險。
- `優先度中`：高影響死碼、重複功能、責任集中或架構耦合。
- `優先度低`：不影響主要功能的整理、格式或後續可改善項目。
- `難易度簡單`：小型清理或單點修改。
- `難易度中`：中型重構，涉及少量呼叫端或資料契約。
- `難易度困難`：大型拆分、跨頁面流程或服務邊界調整。

2. `優先度最高`：停止問卷、語音、飲食紀錄與飲食摘要的敏感資料 log。
3. `優先度最高`：檢視 `core/api_client.dart` 的 token refresh 與 UI 導航耦合；raw response body logging 已完成。
4. `優先度中`：確認餐點搜尋服務的 timeout、錯誤分類與授權需求。
