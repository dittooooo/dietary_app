# 前後端功能落差整理清單 (依頁面分類)

本文件整理了 **Dietary App** 各主要頁面中，「前端已完成介面與互動邏輯，但後端尚未實作對應支持」的功能清單。

---

## 1. 登入 (Login / Register)
*   **密碼進階管理**：
    *   **前端**：登入頁面已預留基礎結構。
    *   **後端**：缺失「忘記密碼」、「修改密碼」以及「發送電子郵件驗證碼」的邏輯與 API。
*   **登入狀態安全性**：
    *   **前端**：已實作 JWT Token 的儲存與帶入請求 Header。
    *   **後端**：目前的 Token 驗證僅為基礎，尚未實作 Token 刷新（Refresh Token）或多裝置登入管理。

---

## 2. 個人首頁 (Profile Page)
*   **帳號註銷功能 (Delete Account)**：
    *   **前端**：已實作「刪除帳戶」按鈕與二次確認視窗，並具備前端錯誤降級提示。
    *   **後端**：缺失對應的 `DELETE` 接口，無法真正將使用者資料從資料庫徹底移除。
*   **頭像上傳與持久化 (Profile Image)**：
    *   **前端**：點擊頭像可呼叫手機相簿選取照片。
    *   **後端**：資料庫缺失儲存圖片路徑的欄位，亦無處理檔案上傳的 API。
*   **管理員權限與後台管理**：
    *   **前端**：已實作「管理員專屬選單」（使用者管理、餐廳管理、菜單管理等頁面），清單內目前為模擬資料。
    *   **後端**：`User` 表格缺失 `role` 角色欄位，後端無法進行實質權限驗證，亦無提供「列出全體使用者」的管理 API。

---

## 3. 飲食紀錄 (Dietary Records / Camera / Report)
*   **食物影像自動辨識 (Food Recognition)**：
    *   **前端**：具備拍照、掃描動畫以及顯示「茶葉蛋、豆漿」等標籤的結果頁面。
    *   **後端**：缺失影像分析與辨識 API，無法根據照片回傳食物清單。
*   **營養數據自動計算 (Nutrient Calculation)**：
    *   **前端**：UI 可顯示熱量、碳水、蛋白質、脂肪等比例卡片。
    *   **後端**：缺失食物營養庫，無法提供精確的營養成分數值。
*   **趨勢分析報告 (Dietary Reports)**：
    *   **前端**：具備日/月/年切換的統計折線圖與本週總結文字。
    *   **後端**：缺失大數據統計邏輯（Aggregation），無法幫前端計算出週/月/年的累積攝取量趨勢。

---

## 4. 預設首頁 (聊天畫面 - Home View)
*   **AI 飲食建議對話 (AI Chat)**：
    *   **前端**：具備與小精靈對話的氣泡介面。
    *   **後端**：缺失與 AI 模型（如 Gemini/ChatGPT）的對接，目前無法根據使用者提問給予真實的飲食回覆。
*   **智慧餐廳與營養查詢**：
    *   **前端**：模擬回覆中包含附近餐廳推薦與特定食物（如：薯條）的營養資訊。
    *   **後端**：缺失地理位置服務與食物庫搜索 API，無法根據使用者輸入提供真實建議。
*   **小精靈成長與餵食紀錄**：
    *   **前端**：具備精靈餵食頁面。
    *   **後端**：缺失儲存小精靈「成長數值」或「餵食歷史」的資料表與邏輯。

---

> **開發狀態說明**：前端代碼已全面採用「後端為主，前端為輔」的架構重構。所有上述功能在前端皆已預留 API 連線位置，後端補齊 API 後即可立即對接。
